## BUG-001 · 托盘右键退出后进程未立即退出

- **等级**：中（影响用户预期，不影响数据安全；数据在退出时已落盘）
- **登记版本**：v0.5.0
- **环境**：仅在 **Windows 实机** 复现；macOS 交叉编译产物下无法运行，因此无法在本机验证。

### 现象

在托盘图标上右键选择「退出」后：

1. 界面（灵动岛窗口）先是消失；
2. 约 1 秒后窗口被**自动重新拉起**；
3. 之后**不定期提示“已挂起”**（挂起 = 无响应）；
4. 大约 **30 秒左右**进程才彻底消失。

### 已完成：代码层排查结论（未发现内部自重启机制）

对源码退出链路进行了完整梳理，确认：

- 退出入口 `quit()` → `save_now()` → `close_for_quit()` → `PostMessage(WM_CLOSE)`。
- `WM_CLOSE` → `DefWindowProc` → `DestroyWindow` → `WM_DESTROY` → `PostQuitMessage(0)` → 主消息循环 `break`。
- `quit()` 内另有 **3 秒看门狗线程**以 `process::exit(0)` 兜底（这是为“万一主循环不退出”的保险，3 秒内正常退出则不影响）。
- 全仓库搜索确认 **没有任何自重启 / 守护 / 计划任务 / watchdog 拉起逻辑**：
  - `autostart.rs` 仅写开机自启注册表 `Run` 键；
  - 所有 `ShellExecuteW` 调用点均为打开 notepad / explorer / 目录，与进程拉起无关。

**结论**：上述现象（先消失 → 1 秒后拉起 → 提示挂起 → 30 秒后消失）与当前 winisland 代码不符，**疑似来自外部守护 / 自启机制**（例如：勾选了“失败后自动重启”的守护程序、任务计划程序、杀软或系统对该 exe 的“挂起恢复”行为），而非内部代码 bug。

### 待 Windows 实机的下一步验证步骤

1. 复现：托盘右键退出，记录是否重复出现“拉起 / 挂起 / 30 秒延迟”。
2. 关闭系统与安全软件（杀软、企业管控）后重试，判断是否外部介入。
3. 检查是否配置了开机自启 / 计划任务 / 守护程序，逐一停用排除。
4. 进程仍无法立即退出时，抓取主线程调用栈（ProcExp / WinDbg），定位卡住的调用。
5. 若确认与内部某线程（如 3 秒看门狗、IMAP、节假日同步）有关，再进代码修复。

### 结论 / 处置

当前判定为「待复现，疑似外部机制」。登记为待办，等具备 Windows 实机后按上述步骤验证；若确认为内部问题再修复。
